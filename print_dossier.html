STEP 7 · Linux io_uring Asynchronous Engine (Distinction)
./copyfast -b uring -s 1M -q 16 -v /tmp/copyfast_demo/sample_100M.dat /tmp/copyfast_demo/dest_uring.dat
Explanation: Asynchronous batch submission over Linux SQ/CQ rings with depth 16 and 1 MB buffers.
Speaker Script: "Now we demonstrate our primary Distinction feature: native Linux io_uring. Unlike legacy POSIX AIO which spawns hidden user-space threads, io_uring utilizes memory-mapped kernel ring buffers. We submit 16 asynchronous requests at a time. The kernel processes them concurrently with storage hardware, achieving extreme I/O throughput."
STEP 8 · Generate 1.0 GB Sparse File (99% Holes)
dd if=/dev/urandom of=/tmp/copyfast_demo/sparse_1G.img bs=1M count=1 seek=0 2>/dev/null && dd if=/dev/urandom of=/tmp/copyfast_demo/sparse_1G.img bs=1M count=1 seek=999 2>/dev/null
Explanation: Creates a 1.0 GB virtual disk with 1MB at offset 0 and 1MB at 999MB, leaving a 998 MB unallocated hole.
Speaker Script: "Next, let's explore sparse files. Modern virtual machine disk images, databases, and container layers often contain vast regions of empty unallocated space. Here we create a 1.0 GB file that has real data at the beginning and the end, with a 998 MB hole in the middle."
STEP 9 · Inspect Sparse File Allocation
ls -lhs /tmp/copyfast_demo/sparse_1G.img
Explanation: Displays actual disk blocks allocated (~2.0 MB) vs apparent file length (1.0 GB).
Speaker Script: "Look closely at ls -lhs. Even though the apparent file size is 1.0 GB, physical disk consumption is only 2.0 MB. The filesystem simply stores an extent map without allocating physical zeroes."
STEP 10 · Sparse Hole Detection & Transfer
./copyfast -S -v /tmp/copyfast_demo/sparse_1G.img /tmp/copyfast_demo/dest_sparse.img
Explanation: Uses lseek(SEEK_HOLE) to skip holes without writing zeroes, computing in-memory SHA-256.
Speaker Script: "Standard copy tools like naive cp will read and write 1 GB of zeroes, wasting I/O bandwidth and wearing out SSD flash memory. With CopyFast's -S flag, our engine uses SEEK_DATA and SEEK_HOLE to jump over empty space. Notice the summary: it skipped 998 MB of holes and finished in under 5 milliseconds, clocking an effective transfer rate of hundreds of gigabytes per second!"
STEP 11 · Verify Sparse Destination Usage
