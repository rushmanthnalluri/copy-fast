Engine Architecture & Concurrency Model

1. Overlapped Reader-Writer Pipeline (Pthreads)

Standard tools alternate synchronously between read(2) and write(2). While reading from source storage, the destination storage channel sits idle; while writing, the source channel sits idle. CopyFast spawns dedicated reader and writer POSIX threads operating across a bounded ring buffer of 4096-byte page-aligned memory slots allocated with posix_memalign(). Synchronization uses mutexes and condition variables (cond_not_empty, cond_not_full) with 100ms timed waits to guarantee immediate response to SIGINT and prevent deadlock if a worker thread encounters an error.

2. Linux io_uring Asynchronous Engine

To eliminate syscall transitions and context switching, CopyFast implements a native io_uring backend. The application kernel interface uses memory-mapped Submission Queue (SQ) and Completion Queue (CQ) rings. Reads and writes are batched with io_uring_prep_read() and io_uring_prep_write(). The kernel processes I/O operations directly with storage hardware without blocking user threads.

3. Sparse Extent Detection

CopyFast leverages the Linux virtual filesystem extent interface: lseek(fd, offset, SEEK_HOLE) and lseek(fd, offset, SEEK_DATA). It detects holes and advances the destination offset via lseek(SEEK_SET) without writing zeroes. Trailing holes at EOF are preserved using ftruncate(). For cryptographic integrity passes with -v, checksum_update_zeros() computes SHA-256 hashes of hole blocks directly in-memory, avoiding all disk I/O.

4. Crash-Resilient Journaling

When interrupted by SIGINT, CopyFast synchronizes destination blocks with fdatasync() and writes a state journal to <dest>.copyfast.resume. The journal header contains magic bytes 0x43504652, source file inode, source size, modification timestamp, destination byte offset, and a CRC32 integrity check. On resumption with --resume, CopyFast verifies the CRC32, skips already copied bytes with lseek(), resumes transfer, and cleans up the journal upon completion.
